01

모바일 웹앱의 개념과 특징

웹 기술로 동작하는 모바일 서비스의 특성과 구현 방식을 이해한다.

핵심 개념모바일 웹앱 = 웹브라우저에서 실행되는 응용 서비스

HTML5는 구조, CSS3는 디자인, JavaScript는 동작을 담당한다. 웹앱은 정보 제공을 넘어 검색, 입력, 서버 통신, 데이터 처리 등의 상호작용을 수행한다.

▣
⌕BROWSER
모바일 웹앱

URL로 접속하며 다양한 모바일 브라우저에서 공통 웹 코드를 사용할 수 있다.

▦OS APP
네이티브 앱

Kotlin, Swift 등으로 개발하며 운영체제 고유 API와 배포 체계를 활용한다.

◎WEB + APP
PWA

웹앱에 설치 가능한 경험, 캐시, 일부 오프라인 기능 등을 추가할 수 있다.

개발 방식 비교

항목모바일 웹앱네이티브 앱PWA
실행모바일 브라우저운영체제 앱브라우저 / 설치 형태
개발 기술HTML · CSS · JSKotlin · Swift 등웹 기술 + PWA 기능
접근 방식URL앱 설치 후 실행URL 또는 설치 아이콘
기기 기능브라우저 지원 범위플랫폼 API 활용브라우저 지원 범위

※ PWA의 설치·오프라인 지원과 기기 접근 기능은 브라우저 및 운영체제에 따라 달라진다.

02

UI와 UX 디자인

보이는 인터페이스와 사용자가 경험하는 과정을 함께 설계한다.

UI▤
User Interface

사용자가 직접 보고 조작하는 화면과 구성 요소

  • 버튼, 입력창, 카드, 아이콘
  • 색상, 글꼴, 여백, 배치
  • 상단·하단 탐색 메뉴
UX↗
User Experience

사용자가 목적을 달성하기까지의 전체 이용 경험

  • 화면 이동과 작업 수행 순서
  • 사용 편의성, 작업 효율성
  • 접근성, 오류 방지, 만족도
보기 쉬운 화면(UI)+이용하기 쉬운 흐름(UX)→사용자 중심 서비스
사례로 이해하기

음식 주문 서비스

UI: 음식 이미지, 가격, 검색창, 주문 버튼을 보기 좋게 배치한다.

UX: 원하는 음식을 빠르게 찾고, 적은 단계로 주문을 완료하게 한다.

핵심 정리와 학습 확인

모바일 웹앱 기획·설계의 핵심 개념을 최종 점검한다.

1
기획은 문제 정의에서 출발

무엇을 만들지보다 어떤 사용자 문제를 해결할지 먼저 결정한다.

2
UI와 UX를 함께 설계

보기 좋은 화면과 목적을 달성하기 쉬운 흐름을 동시에 고려한다.

3
요구사항은 검증 가능하게

기능·비기능 요구사항과 우선순위를 구체적으로 정한다.

4
화면 전에 구조부터

정보구조 → 화면 흐름 → 와이어프레임 → 화면 설계서 순으로 구체화한다.

5
모바일 중심으로 확장

작은 화면의 핵심 기능을 우선하고 터치·접근성·반응형을 검토한다.

6
프로토타입으로 반복 검증

실제 사용자 테스트에서 발견한 문제를 설계에 반영한다.

스스로 확인하는 5문항

Q1. UI와 UX는 어떻게 다른가?

UI는 사용자에게 보이는 화면과 조작 요소이며, UX는 사용자가 목적을 달성하는 과정에서 경험하는 편의성·효율성·만족도 등을 의미한다.

Q2. MVP를 정의하는 이유는 무엇인가?

핵심 가치를 확인하는 데 필요한 기능에 먼저 집중하여 개발 비용과 위험을 줄이고 사용자 피드백을 확보하기 위해서이다.

Q3. 정보구조도와 사용자 흐름도의 차이는?

정보구조도는 메뉴와 콘텐츠의 전체 계층을 나타내고, 사용자 흐름도는 특정 목표를 달성하기 위해 거치는 화면의 순서를 보여준다.

Q4. Mobile First가 중요한 이유는 무엇인가?

제한된 모바일 화면에서 가장 중요한 기능과 정보를 먼저 결정하고, 넓은 화면으로 유연하게 확장하도록 돕기 때문이다.

Q5. 프로토타입 검증 단계에서 무엇을 평가하는가?

작업 성공률, 작업 시간, 오류 횟수, 탐색 용이성, 사용자 만족도 등을 평가하고 그 결과를 설계 개선에 활용한다.

좋은 모바일 웹앱은 코드가 아니라 사용자 문제에서 시작된다.

기획 → 분석 → 정보구조 → UI/UX 설계 → 검증 → 개선의 전체 흐름을 이해하는 것이 핵심이다.
